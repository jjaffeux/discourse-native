Design rationale & Native component mapping

The current page starts with ten equally weighted stat tiles, then pairs unrelated sections into a long grid. These proposals introduce hierarchy, clearer labels and intentional grouping. Every existing summary data category is retained.

01: The best general-purpose replacement. Prioritizes likes received, replies written, days visited and reading time. Secondary stats sit in a disclosure; topic/reply and people tabs reduce repetition. The tradeoff is one click for secondary information.

02: Makes the page feel like a record of participation. A featured topic is followed by other topics, replies and links; reading and people live in a narrower side column. The tradeoff is a longer page on mobile.

03: A compact profile with three focused sections. Identity and key account totals stay visible while browsing. The tradeoff is lower discoverability for content behind tabs.

No new generic component is required for these directions. Their reusable summary sections can be application compositions of the kit. Native implementation will import package:discourse_native/discourse_ui.dart. These HTML studies mirror its geometry and semantic palette; they do not execute Flutter widgets.

The saved dev.discourse.org light/dark palette supplies the colors. Sample data is fictional and shared between directions. No invented time series, streak, growth percentage or period filter is shown: the existing API returns all-time totals plus recent read time. Topic and person clicks show local inspection dialogs. No account data is requested or changed.
