MY PICK 02

Keep it in the header.

“Saved” stays easy to find and leaves the action bar free for attachments and plugins. A neutral check is enough; save success doesn’t need a green banner.

HTML/CSS concepts using the Native kit’s existing control sizes and vocabulary. Draft saving is simulated in this page; nothing is stored or sent.

Component mapping & behavior

01 · Footer status: DIcon / DSpinner with Text and Semantics in the existing footer row. Reserve the status slot; overflow secondary toolbar actions into the existing menu.

02 · Header status: the same status composition beside the header actions. Keep its width stable across saving/saved. No new UI kit component.

03 · Confirmation, then an icon: DButton.iconOnly (transparentBackground), DTooltip and DPopover for details. Application-owned timing fades only the confirmation label after 2.4 seconds; the icon and reserved space remain. Warnings never fade.

All directions: 28px regular controls, 32px large toolbar controls, 8px control radius, neutral success, polite status announcements, reduced-motion support. Show “Draft saved” only after site save succeeds. Keep device-only and failed saves distinct. Existing error detail remains visible with a retry action in these concepts.

Based on ComposerHeader and _Footer in composer_panel.dart; colors use the repository’s saved dev.discourse.org palette. These are review mockups, not Flutter implementation or device verification.
