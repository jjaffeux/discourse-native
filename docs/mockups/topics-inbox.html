What I’d change

01 / A calmer reading order

Title, one line of context, then tags and activity. Keep reply counts and last activity; drop the always-visible views column. Don’t repeat the current category on every row.

02 / Search belongs to the list

Category and tags define the scope automatically. The category and tag controls already show the scope; no helper line is needed. Changing a filter keeps the query and updates the results.

03 / Assignments stay visible

A dedicated “Assigned to” line identifies the person or group. Last-poster activity stays separate. Outlined tags keep their treatment on row hover. Previews remain optional.

04 / Clear unread meaning

A blue dot means a new topic; a numbered badge means unread posts. Fully read titles fade. Tooltips and accessible labels explain each indicator.

UI kit & implementation notes

Rows: DItem.outline with DItemTitle, DItemDescription and DItemFooter. Search: DInputGroup and its input/addons. Feeds: DTabs. Labels: DBadge. Last poster and assignee: DAvatar. Reuse TopicStateDot, TopicUnreadBadge and the fully-read title color. Assignment data comes from the Assign plugin.

Retain TopicCategorySelector and the multi-select TopicTagSelector; the two tag buttons here are a small interactive stand-in. Use the public discourse_ui.dart entrypoint in Flutter.

This HTML approximates the kit; it does not run Flutter components. No component extension is proposed. Category/tag/query coordination is application logic.

Search should query the server across matching topics, not just loaded rows. Debounce typing, discard stale responses, and preserve the selected feed. Match the existing list’s tag and subcategory semantics. This demo uses all selected tags (AND), and searches sample titles/excerpts only.

Use existing spinner, empty and alert components for loading, no results and retry states. Keep the toolbar available throughout. A global search remains a separate navigation action.

Reference: Shadcn Mail Apps. Neutral colors here represent semantic theme tokens; production uses the site palette.
