Why this arrangement

Built from the kit

HTML/CSS approximations of the local Native components. No Flutter components are added or changed.

Worth adding?

A documented adaptive list-header composition: title/actions, navigation, contextual controls, and a shared filter state across inline and sheet presentations.

Start with a styleguide recipe. A generic component is optional, only if more screens need it. No new visual primitive is required for these concepts.

Interaction and implementation notes

Try the feed tabs, All / Topics / Replies, category and tag selectors, reset, drafts, and the Filters sheet. Each preview has independent local state. Topic and create actions open clearly marked previews. No account data or network writes.

Breakpoints use the available content pane, not the whole app window: 760px for the compact header, 900px for the browse rail, and 680px for the full topic table. Enlarged text can require switching earlier.

The 83 / 52 counts reproduce the supplied state. The rows are a small illustrative sample, not all 135 topics. “Replies” means topics with unread replies, preserving the existing route semantics. Top exposes a time-period choice.

In Flutter, compose through package:discourse_native/discourse_ui.dart, preserve route and selection ownership, and keep the kit’s keyboard, focus, theme, RTL and touch behavior. This HTML prototype is not a substitute for native verification.
